# Memory Guide — Data Model

---

## Overview

This document specifies the data schemas for the Memory Guide MVP. All data is stored in-memory (JavaScript objects/arrays) for the MVP — no external database is required.

Three primary entities:
1. **Image** — a photo in the demo library with pre-extracted attributes.
2. **RetrievalSession** — the full state of one retrieval attempt.
3. **Question** — a single clarification question within a session.

---

## 1. Image Schema

Each image is pre-processed at ingestion time. The VLM extracts structured attributes once; these are stored alongside the image and reused across all retrieval sessions.

```typescript
interface Image {
  // ── Identity ──
  id: string;                    // e.g., "img_001"
  filePath: string;              // relative path to image file, e.g., "demo-photos/birthday_park_01.jpg"
  fileName: string;              // human-readable name for logging

  // ── Semantic Description ──
  caption: string;               // 1-2 sentence natural-language description of the photo
                                 // Generated by VLM at ingestion. Used for initial semantic matching.
                                 // Example: "A young girl in a pink frock cutting a birthday cake
                                 //           indoors while an adult woman in a blue sari watches."

  // ── Structured Attributes ──
  // These are the dimensions used for discrimination scoring.

  people: {
    count: "0" | "1" | "2" | "3+";
    ageGroups: Array<"child" | "teen" | "adult" | "elderly">;
    descriptions: string[];      // e.g., ["young girl, ~5 years", "adult woman"]
    genderPresentation: Array<"male" | "female" | "unclear">;
  };

  environment: {
    setting: "indoor" | "outdoor" | "unclear";
    settingType: string;         // e.g., "home", "park", "beach", "restaurant", "temple",
                                 //        "street", "office", "school", "vehicle", "mountain",
                                 //        "garden", "hall"
    details: string;             // e.g., "decorated living room with streamers"
    timeOfDay: "day" | "night" | "golden_hour" | "unclear";
    seasonHint: "summer" | "winter" | "rainy" | "spring" | "unclear";
    weatherHint: "sunny" | "cloudy" | "rainy" | "unclear";
  };

  activity: {
    primary: string;             // e.g., "celebrating", "posing", "eating", "playing",
                                 //        "traveling", "cooking", "dancing", "studying",
                                 //        "shopping", "walking", "swimming", "hiking"
    details: string;             // e.g., "cutting a cake with candles"
  };

  occasion: {
    type: string;                // e.g., "birthday", "wedding", "festival", "graduation",
                                 //        "holiday", "casual", "trip", "anniversary",
                                 //        "engagement", "baby_shower", "picnic", "party"
    details: string;             // e.g., "5th birthday party"
  };

  clothing: {
    descriptions: string[];      // per-person clothing, e.g., ["pink frock", "blue sari"]
    formality: "casual" | "formal" | "traditional" | "sportswear" | "mixed";
    dominantColors: string[];    // clothing colors, e.g., ["pink", "blue"]
  };

  objects: {
    items: string[];             // notable objects, e.g., ["cake", "balloons", "candles", "gift_box"]
    animals: string;             // "none" | "dog" | "cat" | "bird" | "other"
    animalDetails: string;       // e.g., "golden retriever puppy" (empty if no animal)
  };

  visualAttributes: {
    dominantColors: string[];    // overall image colors, e.g., ["pink", "yellow", "white"]
    mood: "happy" | "serious" | "candid" | "playful" | "romantic" | "solemn" | "energetic";
    composition: "selfie" | "posed_portrait" | "posed_group" | "candid" | "landscape" | "close_up";
    hasText: boolean;            // visible text/signage in the image
    lighting: "bright" | "dim" | "natural" | "artificial" | "mixed";
  };

  // ── Approximate Metadata ──
  approximateDate: {
    year: number | null;         // e.g., 2019 or null if unknown
    season: string | null;       // e.g., "summer" or null
    period: string;              // e.g., "childhood", "college", "recent", "2010s"
  };

  approximateLocation: {
    type: string;                // e.g., "home", "city", "nature", "travel"
    region: string;              // e.g., "Bangalore", "Goa", "unknown"
  };

  // ── Derived / Indexing ──
  tags: string[];                // flat list of all searchable terms derived from above,
                                 // e.g., ["birthday", "cake", "child", "indoor", "pink", "frock"]
                                 // Used for fast initial filtering before LLM scoring.

  clusterIds: string[];          // which ambiguity clusters this image belongs to (see demo-dataset-plan.md)
                                 // e.g., ["birthday_cluster", "child_photos_cluster"]
                                 // Used for test validation, not for retrieval logic.
}
```

### 1.1 Attribute-to-Dimension Mapping

The discrimination engine (architecture.md §6–7) operates on **dimensions**. This table maps schema fields to analysis dimensions:

| Dimension Key | Schema Path | Value Type |
|--------------|-------------|------------|
| `people_count` | `people.count` | categorical |
| `people_age_group` | `people.ageGroups` | multi-categorical |
| `setting` | `environment.setting` | categorical |
| `setting_type` | `environment.settingType` | categorical |
| `time_of_day` | `environment.timeOfDay` | categorical |
| `season` | `environment.seasonHint` | categorical |
| `activity` | `activity.primary` | categorical |
| `occasion` | `occasion.type` | categorical |
| `clothing_color` | `clothing.dominantColors` | multi-categorical |
| `clothing_formality` | `clothing.formality` | categorical |
| `objects` | `objects.items` | multi-categorical (per-item) |
| `animals` | `objects.animals` | categorical |
| `mood` | `visualAttributes.mood` | categorical |
| `composition` | `visualAttributes.composition` | categorical |
| `dominant_colors` | `visualAttributes.dominantColors` | multi-categorical |
| `date_period` | `approximateDate.period` | categorical |
| `location_type` | `approximateLocation.type` | categorical |

### 1.2 The `tags` Field

`tags` is a **pre-computed flat array** of all searchable terms extracted from the structured attributes. It enables fast initial filtering without calling the LLM for every image during initial retrieval.

Generation rule: lowercase all values from `people.descriptions`, `activity.primary`, `occasion.type`, `clothing.descriptions`, `objects.items`, `environment.settingType`, `approximateLocation.region`, plus the caption split into keywords.

## 2. Retrieval Session Schema

A session tracks the entire state of one retrieval attempt from start to outcome.

```typescript
interface RetrievalSession {
  // ── Identity ──
  sessionId: string;             // unique session identifier, e.g., "sess_20261004_001"

  // ── Timestamps ──
  startedAt: string;             // ISO 8601 timestamp
  endedAt: string | null;        // null while in progress

  // ── User Input ──
  originalQuery: string;         // verbatim text the user typed initially
                                 // e.g., "That old childhood photo where I was wearing
                                 //        a pink dress and cutting a cake"

  // ── Extracted Clues ──
  clues: Clue[];                 // all clues accumulated across the session
                                 // grows with each answered question

  // ── Candidate Tracking ──
  initialCandidateCount: number; // how many images matched after initial retrieval
  candidates: CandidateEntry[];  // current active candidates with scores
  eliminatedCandidates: string[];// image IDs dropped due to low score
  rejectedByUser: string[];      // image IDs the user explicitly rejected at recognition

  // ── Question History ──
  questions: Question[];         // ordered list of all questions asked (see §3)

  // ── Narrowing History ──
  candidateCountHistory: NarrowingStep[];  // tracks how the set shrank over time

  // ── Status ──
  retrievalStatus: "not_started" | "in_progress" | "found" | "close_match" | "unresolved" | "abandoned";
  selectedTarget: string | null; // image ID of the photo the user confirmed (null if not found)

  // ── Dimension Tracking ──
  dimensionsAsked: string[];     // dimensions already asked about (including "I don't remember")
  dimensionsProvidedByUser: string[];  // dimensions covered by user's initial description or volunteered info

  // ── Round Tracking ──
  roundCount: number;            // number of clarification rounds completed
  consecutiveIdkCount: number;   // consecutive "I don't remember" answers (resets on a real answer)

  // ── Testing / Analytics ──
  totalTimeMs: number | null;    // total session duration in milliseconds
  userReformulations: number;    // times the user modified their original query (should be 0 ideally)
  manualScrollUsed: boolean;     // whether the user browsed candidates manually
  mostHelpfulQuestion: number | null;  // index into questions[] of the question that caused
                                       // the largest candidate reduction
}
```

### 2.1 Clue Sub-Schema

```typescript
interface Clue {
  dimension: string;             // matches a dimension key from §1.1
  value: string;                 // the remembered value, e.g., "indoor", "pink frock"
  source: "user_initial" | "user_answer" | "inferred";
  confidence: "stated" | "inferred";
  addedAtRound: number;          // 0 for initial clues, 1+ for clues from answers
}
```

### 2.2 CandidateEntry Sub-Schema

```typescript
interface CandidateEntry {
  imageId: string;
  score: number;                 // 0-10 relevance score
  matchingClues: string[];       // which clues this candidate matches
  contradictingClues: string[];  // which clues this candidate contradicts
  addedAtRound: number;          // when this candidate entered the set (usually 0)
  lastScoredAtRound: number;     // last round when score was updated
}
```

### 2.3 NarrowingStep Sub-Schema

```typescript
interface NarrowingStep {
  round: number;                 // 0 = after initial retrieval, 1+ = after each question
  candidateCount: number;        // number of active candidates at this point
  trigger: string;               // what caused the narrowing, e.g., "initial_retrieval",
                                 //   "question:setting", "question:occasion", "user_rejection"
}
```

## 3. Question Schema

Each question is stored as part of the session's `questions` array. This schema captures everything needed for both the retrieval loop and post-session analytics.

```typescript
interface Question {
  // ── Identity ──
  questionId: string;            // e.g., "q_001" (unique within session)
  round: number;                 // which clarification round (1-indexed)

  // ── What Was Asked ──
  dimensionTested: string;       // the attribute dimension being tested,
                                 // e.g., "setting", "occasion", "objects:cake"
  questionText: string;          // the natural-language question shown to the user

  // ── Why It Was Asked ──
  candidateDistribution: Record<string, number>;
                                 // value distribution for this dimension across candidates
                                 // e.g., { "indoor": 12, "outdoor": 10, "unclear": 2 }
  discriminationScore: number;   // 0.0–1.0, computed as 1 - max_fraction
  memorabilityWeight: number;    // 0.0–1.0, from the memorability table
  finalScore: number;            // discrimination × memorability (the ranking score)

  // ── User Response ──
  userAnswer: string;            // verbatim answer from the user
  parsedValue: string | null;    // structured value extracted from the answer
                                 // null if user said "I don't remember"
  answerType: "answered" | "dont_remember" | "skipped";

  // ── Impact ──
  candidatesBefore: number;      // candidate count before this question was processed
  candidatesAfter: number;       // candidate count after processing the answer
  reductionPercent: number;      // percentage reduction, e.g., 54.2

  // ── Timing ──
  timestamp: string;             // when the question was asked (ISO 8601)
}
```

### 3.1 Analytics Derived from Question Data

After a session completes, these can be computed from the question records:

| Metric | Derivation |
|--------|------------|
| Total questions asked | `questions.length` |
| Average reduction per question | `mean(questions[*].reductionPercent)` where `answerType == "answered"` |
| Most helpful question | `max(questions[*].reductionPercent)` |
| "I don't remember" rate | `count(answerType == "dont_remember") / questions.length` |
| Question that caused largest drop | `argmax(questions[*].candidatesBefore - questions[*].candidatesAfter)` |
| Was the discrimination score predictive? | Correlation between `discriminationScore` and actual `reductionPercent` |

## 4. Entity Relationships

```
┌─────────────────┐
│     Image       │
│  (pre-indexed)  │
└────────┬────────┘
         │ referenced by
         │
┌────────▼────────────────────┐       ┌──────────────────┐
│    RetrievalSession         │──────▶│    Question[]     │
│                             │ has   │                  │
│  candidates[].imageId ──────┼──┐    └──────────────────┘
│  eliminatedCandidates[] ────┼──┤
│  rejectedByUser[] ──────────┼──┤
│  selectedTarget ────────────┼──┘
│                             │
│  clues[] ───────────────────┼──── accumulated user clues
│  candidateCountHistory[] ───┼──── narrowing trace
└─────────────────────────────┘
```

- **Image** is a static, pre-indexed entity. It does not change during retrieval.
- **RetrievalSession** is the mutable session state. It grows with each round.
- **Question** is immutable once recorded. Each question captures a snapshot of the system's reasoning at the time it was asked.

## 5. In-Memory Storage (MVP)

For MVP, all data lives in JavaScript memory. No persistence across page reloads is required (though `localStorage` can optionally be used for session logs).

```typescript
// Image index — loaded once at app start
const imageLibrary: Image[] = [ /* all demo images */ ];

// Active session — one at a time
let currentSession: RetrievalSession | null = null;

// Session history — for analytics
const sessionHistory: RetrievalSession[] = [];
```

### 5.1 Why No Database

- The demo library is small (50–60 images). Linear scan is fast enough.
- Sessions are ephemeral for MVP. No cross-session learning is needed.
- Avoiding database setup keeps the MVP deployable as a single web app.

### 5.2 Optional: localStorage for Session Logs

For user testing, completed sessions can be serialized to `localStorage` so test facilitators can export results without a backend:

```typescript
function saveSession(session: RetrievalSession): void {
  const history = JSON.parse(localStorage.getItem("mg_sessions") || "[]");
  history.push(session);
  localStorage.setItem("mg_sessions", JSON.stringify(history));
}
```
